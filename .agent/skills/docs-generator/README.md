# Docs Generator

> **Structured workflow for co-authoring documentation** - From context gathering to reader-tested final doc.

## 🚀 Quick Start

Trigger this skill with phrases like:
- "Help me write a design doc"
- "Draft a proposal for..."
- "Create a technical spec"
- "Write up the RFC for..."

## ✨ What It Does

Guides you through a proven 3-stage workflow that produces documents others can actually understand:

1. **Context Gathering** - Efficiently transfer what's in your head
2. **Refinement & Structure** - Build section by section with brainstorming
3. **Reader Testing** - Verify the doc works for people without context

## 🔧 How It Works

### Stage 1: Context Gathering
- Answer 5 meta-questions about your document
- Dump all relevant context (no need to organize)
- AI asks clarifying questions to fill gaps

### Stage 2: Refinement & Structure
- Work section by section
- For each: clarify → brainstorm options → curate → draft → refine
- Quality checks at 80% completion

### Stage 3: Reader Testing
- Predict what questions readers will ask
- Test with a fresh AI (no context from your conversation)
- Fix any blind spots

## 📝 Examples

**Example 1: Writing a Design Doc**
```
User: I need to write a design doc for our new auth system
→ Skill asks 5 meta-questions
→ User dumps context about requirements, constraints
→ Skill asks clarifying questions
→ Build sections one by one
→ Reader test catches missing assumptions
→ Final polished doc
```

**Example 2: Decision Document**
```
User: Help me draft a decision doc for switching to Postgres
→ Focus on core proposal first (most unknown)
→ Brainstorm 15+ considerations
→ User curates to strongest arguments
→ Reader test verifies logic holds without context
```

## 💡 Pro Tips

- **Don't self-edit during info dump** - Just get it all out
- **Use shorthand for curation** - "Keep 1,4,7" or "Remove 3 (duplicates 1)"
- **Let AI learn your style** - Describe changes instead of editing directly
- **Reader testing is optional but valuable** - Skip if time-constrained
